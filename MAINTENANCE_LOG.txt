QQ空间插件单 main 维护日志
========================

项目目标
--------
用户希望最终部署包尽量只保留：
- main.py
- _conf_schema.json
- metadata.yaml
- requirements.txt
- default_style/
- logo.png
- MAINTENANCE_LOG.txt（从 Round 2 起新增，便于未来 LLM 理解历史）

维护原则
--------
1. 慢一点，宁可少改，不要一次性大改。
2. 每次原子修改都说明为什么改。
3. 涉及可能刷屏/反复评论/自动发消息的功能，默认从安全角度审查。
4. 用户不懂代码，最终交付物要尽量可直接覆盖部署。
5. main.py 顶部只放简短 AGENT NOTE；详细历史写在本文件，避免 main.py 注释无限膨胀。

Round 8 - 2026-05-23
--------------------
触发原因：
- 用户日志显示 AutoComment 在 LLM Provider 403/suspended 时会对多条说说连续报错。
- 用户测试 read_prob=1.0 时，没有出现重复评论重大事故，但发现某些群聊触发没有展示自己的说说。

判断：
- 群聊概率读说说的核心目标是“给台阶/展示”，不能因为 LLM 评论失败就完全不发群卡片。
- 原 prob_read_feed 中 _auto_comment_if_allowed 如果评论生成失败会抛出，导致群展示也被跳过。
- 原 prob_read_feed 遇到 Empty 也会 append_ignore_users，可能在用户刚开放空间或接口抽风时把用户长期忽略，误伤概率触发。

处理：
- main.py: _auto_comment_if_allowed 现在捕获评论失败，返回 (False, False)，不再阻断群展示。
- main.py: 群聊概率读说说现在根据真实状态生成自然文案：
  - 本次评论成功：触发读说说：已评论/已评论并点赞。
  - 之前已评论但本次不重复评论：仍使用自然“已评论/已评论并点赞”文案，不暴露内部状态。
  - LLM 故障或受限导致无法评论且之前也没评论：触发读说说：搬来给大家看看。
- main.py: prob_read_feed 不再因为 Empty 把用户加入 ignore_users，只在“不存在”时加入，降低误伤。
- main.py: AutoComment 遇到 LLM 调用失败、403、Permission denied、suspended 时中止本轮，避免一轮对多条说说连续报错。

说明：
- LLM 欠费/供应商停用时，定时评论会停止本轮；群聊概率展示仍可继续发挥“给台阶”作用。
- D 档风险分词和温柔话术池仍未写入，留到下一轮。
